# 思考エンジンの規格と登録のしかた

**日本語** | [English](ENGINE_SPEC.en.md)

Universal Engine Dock(以下「本体」)に、自作・公開のぷよぷよ・テトリスの思考エンジン(AI、ボット)を足すための説明です。
テトリスは TBP(Tetris Bot Protocol)、ぷよは標準入出力の JSON で話します。

この規格は、USB の考えに倣っています。機器ごとに違った差し込み口を USB が1つに揃えたように、エンジンごとに違う渡し方を揃え、
**規格に合わせて作れば、だれのエンジンでも差し替えて使える**ようにするためのものです。
そのために、次の3つを守ります。

- **1つのゲームに口は1つ** — 既に広く使われている規格があればそれを使う(テトリスは TBP)。無ければここで決める(ぷよ)
- **作る言語を問わない** — 標準入出力と JSON だけで話す
- **後から足しても壊れない** — 知らない項目・知らないメッセージは無視する。だから、項目を足しても今のエンジンが動き続ける

規格どおりに動くサンプルが [samples/](samples/) にあります(Python の標準ライブラリだけで動く、弱いエンジンです)。

## 1. 共通の決まり

エンジンは、本体が**別のプロセス**として起動し、標準入出力で話す実行ファイルです。
自分の画面を持ち、ゲームを直接操作するプログラムは登録できません。

| 項目 | 決まり |
|---|---|
| 通信 | 標準入力で要求を受け取り、標準出力に答える |
| 形式 | JSON を **1行に1つ**。改行は `\n`(`\r\n` も可)。行の途中で改行しない |
| 文字コード | UTF-8(BOM なし) |
| 出力の送り出し | 1行書くたびに**必ず flush する**(しないと本体に届かず、時間切れになる) |
| 標準出力 | JSON 以外を書かない。ログや説明は標準エラーへ |
| 知らない項目 | 要求に知らない項目・知らない種類のメッセージがあっても、無視して動く |
| ウィンドウ | コンソールの窓は作られない。入力待ちの画面を出さない |
| 終了 | 終了の合図、または標準入力の終わり(EOF)で、自分から終わる。終わらなければ強制終了される |

要求は1つずつ送られ、ぷよは答えを受け取るまで次の要求は来ません。テトリスは思考中にも次のメッセージが来ます。

## 2. 登録のしかた

### 画面から登録する

1. メイン画面の「エンジンの登録…」を押し、ゲーム種別を選ぶ
2. 「追加…」を押し、次の順に答える
   - **実行ファイル** — エンジンの exe
   - **名前** — 一覧に出す名前。同じゲーム種別の中で重ならないもの(プラグインのエンジンの名前は使えない)
   - **起動引数** — 無ければ空のまま
   - **評価の重み** — 重みのファイルを渡すか(下の表。分からなければ「いいえ」)
3. 「Save」を押す(押さないと登録されません)
4. メイン画面のサイドの「思考エンジン」で選ぶ

### 同梱のエンジンを新しい版に差し替える

同梱の YamaNEKO(ぷよ)と KasugAI(テトリス)も、初めて起動した時から登録の一覧に入っています。
配布物に入っているものを使っている間は、名前の後に「(同梱)」と出ます。

- **新しい版に差し替える** — 一覧で選んで「変更…」を押し、新しい版の実行ファイルを選ぶ。
  名前は変わらないので、メイン画面の選択はそのまま残ります。重みは「いいえ」で今のまま使います
- **配布物のものに戻す** — 「同梱に戻す」を押す。消してしまった時も戻ります
- **消す** — 「削除」を押す。消した同梱のエンジンは、次に起動しても入れ直しません

シミュレーターも、登録にある YamaNEKO・KasugAI を使います。
YamaNEKO だけの設定(配ぷよ読み・CPU の使用など)と KasugAI だけの開幕の指定は、
名前をそのままにし、実行ファイルの名前を同梱のものと同じ始まり(`yamaneko`・`tetrisai-bot`)にした時に使えます。

| | テトリス | ぷよ |
|---|---|---|
| 起動のしかた | `<exe> [--config <重み>] [起動引数…]` | `<exe> [起動引数…]` |
| 作業フォルダ | 本体を起動したフォルダ(決め打ちしない) | exe のあるフォルダ |
| 評価の重み | `--config <ファイルの絶対パス>` として渡す | **使わない**(必要なら起動引数で渡す) |

起動引数の書き方:

- 空白で区切る。空白の入るパスは `"` で囲む
- `\` は特別な文字なので、パスは `/` で書く(例: `--weights "C:/my engine/w.json"`)

テトリスのエンジンが `--config` を知らないなら、重みは「いいえ」にしてください。

### Python などで書いたエンジンを登録する

実行ファイルに `python.exe`、起動引数にスクリプトを指定します。

| 項目 | 例 |
|---|---|
| 実行ファイル | `C:\Python312\python.exe` |
| 起動引数 | `-u "C:/UniversalEngineDock/docs/samples/tetris_engine_sample.py"` |

Python では `-u` を付けるか、`print(..., flush=True)` を使ってください。`pythonw.exe`・`.bat` は使えないことがあります。

### 設定ファイル

登録した内容は `config/engines.json` に残ります。本体を閉じている間なら、直接書いてもかまいません。

```json
{
  "engines": [
    {"game": "puyo", "name": "YamaNEKO", "exe": "engines/yamaneko/engine/bin/yamaneko-bridge.exe", "args": [], "weights": ""},
    {"game": "puyo", "name": "My Puyo AI", "exe": "C:/bots/mypuyo.exe", "args": [], "weights": ""},
    {"game": "tetris", "name": "KasugAI", "exe": "engines/kasugai/tetrisai-bot.exe", "args": [], "weights": "engines/kasugai/run16.toml"},
    {"game": "tetris", "name": "My Bot", "exe": "C:/bots/mybot.exe", "args": ["--threads", "4"], "weights": ""}
  ],
  "bundled": ["puyo/YamaNEKO", "tetris/KasugAI"]
}
```

- 相対パスは、本体のフォルダ(`UniversalEngineDock.exe` のあるフォルダ)から見ます
- `bundled` は、登録へ入れた同梱のエンジンの印です。消すと、次に起動した時に同梱のエンジンを入れ直します

## 3. テトリスの規格(TBP)

[Tetris Bot Protocol(TBP)](https://github.com/tetris-bot-protocol/tbp-spec) に従うエンジンを登録できます。
ここでは、本体が実際に使う範囲を説明します。

### Cold Clear 2 を使う

[Cold Clear 2](https://github.com/MinusKelvin/cold-clear-2)(Apache License 2.0 または MIT License)は、手を加えずそのまま動きます
(確認した版: 配布元の `ed8b193`)。実行ファイルは配布されていないので、自分でビルドします。本体には同梱していません。

1. [Rust](https://www.rust-lang.org/ja/tools/install) と [Git](https://git-scm.com/) を入れ、PowerShell で次を1行ずつ実行する

   ```powershell
   git clone https://github.com/MinusKelvin/cold-clear-2
   ```

   ```powershell
   cargo build --release --manifest-path cold-clear-2/Cargo.toml
   ```

2. 「エンジンの登録…」で、ゲーム種別にテトリスを選び、`cold-clear-2/target/release/cold-clear-2.exe` を追加する。起動引数は空でよい
3. 評価の重みは、次のどちらか
   - **いいえ** — Cold Clear 2 の標準の打ち方
   - **はい** → `cold_clear_beginner.json`(最初に開くフォルダにあります。無ければ `_internal/assets/` の中) —
     1ラインの T スピンとミニ T スピンの加点を外した、初心者向けの打ち方

2手目以降の読み筋は、TBP に無い独自の拡張(`plan`)なので、配布元のままの Cold Clear 2 では出ません。次の一手は同じように出ます。

### 流れ

```
エンジン → {"type":"info", ...}          起動したら自分から送る(5秒以内)
本体     → {"type":"rules"}
エンジン → {"type":"ready"}              5秒以内
本体     → {"type":"start", ...}         局面を渡す。ここから考え始める
本体     → {"type":"suggest"}            その時点の最善手を聞く(約0.1秒ごとに何度も来る)
エンジン → {"type":"suggestion", ...}    すぐ返す(5秒以内)
本体     → {"type":"play", ...}          提示した手のとおりに置かれた
本体     → {"type":"new_piece", ...}     新しい NEXT が見えた
   …
本体     → {"type":"quit"}
```

- `start` は、新しい手番・せり上がり・盤面の食い違いのたびに何度も来る。来たら前の局面は捨てる
- `suggest` は途中経過でよいので待たずに返す。まだ手が無ければ `"moves": []` を返す(次にまた聞かれる)
- `suggest` 1回に、`suggestion` を**ちょうど1つ**返す。聞かれていない時に送らない

### エンジン → 本体

**info**

```json
{"type":"info","name":"My Bot","version":"1.0","author":"me","features":[]}
```

**suggestion**

```json
{"type":"suggestion",
 "moves":[{"location":{"type":"T","orientation":"north","x":4,"y":0},"spin":"none"}],
 "move_info":{"nodes":12345,"nps":1000000}}
```

| 項目 | 必須 | 内容 |
|---|---|---|
| `moves` | ○ | 手の一覧。本体が使うのは**先頭だけ** |
| `location.type` | ○ | 置くミノ(`I O T L J S Z`)。操作ミノと違えば「HOLD して置く」と表示する |
| `location.orientation` | ○ | `north`(出現時の向き)/ `east`(右回し)/ `south` / `west` |
| `location.x`, `location.y` | ○ | ミノの中心の位置。x は左から0〜9、y は**下から**0 |
| `spin` | ○ | `none` / `mini` / `full` |
| `move_info.nodes`, `nps` | | 読んだ局面数・1秒あたり(ログに出る) |
| `plan` | | 独自の拡張: 読み筋。`moves` の要素と同じ形を、今の手から順に並べる(2手目以降の表示に使う) |
| `aim` | | 独自の拡張: 狙いの文字列。情報パネルに出す(改行 `\n` 可) |
| `ren_target` | | 独自の拡張: 狙っている REN の数(整数) |

置ける手かどうかは本体でも確かめます。既存のブロックと重なる・宙に浮く・操作ミノでも HOLD でもないミノの手は表示しません。

### 中心と4マス

`north` の時、中心 (x, y) から見た4マス `(dx, dy)`(dy は上が正):

| ミノ | 4マス |
|---|---|
| I | (-1,0) (0,0) (1,0) (2,0) |
| O | (0,0) (1,0) (0,1) (1,1) |
| T | (-1,0) (0,0) (1,0) (0,1) |
| L | (-1,0) (0,0) (1,0) (1,1) |
| J | (-1,0) (0,0) (1,0) (-1,1) |
| S | (-1,0) (0,0) (0,1) (1,1) |
| Z | (-1,1) (0,1) (0,0) (1,0) |

ほかの向きは、各マスを次のように回します: `east` = (dy, -dx)、`south` = (-dx, -dy)、`west` = (-dy, dx)。

### 本体 → エンジン

**start**

```json
{"type":"start","hold":null,"queue":["T","I","O","S","Z","J"],
 "combo":0,"back_to_back":false,"board":[[null,null,"I"],["…"]]}
```

| 項目 | 内容 |
|---|---|
| `hold` | HOLD のミノ。無ければ `null` |
| `queue` | 操作ミノ + 見えている NEXT(ふつう6個。演出で読めない枠があれば少ない) |
| `board` | 40行 × 10列。**先頭の行が最下段**。値は `null`(空)、ミノの文字、`"G"`(おじゃま・色の分からないブロック) |
| `combo`, `back_to_back` | 支援モードでは常に `0`・`false`(画面からは分からない) |

- HOLD した直後の手番では、もう一度 HOLD させないため、`hold` に操作ミノと同じミノが入ることがある
- 盤面は画面から読んだもので、正しいとは限らない。矛盾した局面(埋まった行、浮いたブロック、袋の順に合わない `queue`)でも落ちないこと

**play** — `{"type":"play","move":{…}}`。`move` は、エンジンが `suggestion` で返した手そのもの。操作ミノが1つ進む

**new_piece** — `{"type":"new_piece","piece":"L"}`。`queue` の最後に1つ足す

**quit** — 終了する

## 4. ぷよの規格

独自の形式です(YamaNEKO が使うものと同じ)。**問い合わせ1回に1行答えて完結**します。前の問い合わせの状態を覚える必要はありません。

> 公開されている [ama](https://github.com/citrus610/ama) の実行ファイルは、この形式では話しません。
> ama を使うには、ama の探索を呼び出してこの形式で話すプログラム(ブリッジ)を作り、そちらを登録してください。

### 流れ

```
エンジン → {"ready":true}     準備ができたら自分から送る(60秒以内)
本体     → {"field":…}        要求(1行)
エンジン → {…}                答え(1行、10秒以内。手番の間に間に合うよう1秒未満が目安)
   …
本体     → quit               終了(JSON ではなく quit の4文字)
```

名前が `yamaneko` で始まらない実行ファイルは、300回の問い合わせごとに起動し直されます(メモリが増え続けるのを抑えるため)。起動は速くしてください。

### 盤面・座標・組ぷよ

| もの | 表し方 |
|---|---|
| 盤面 `field` | 13個の文字列。**先頭が一番上**(13段目 = 隠し段)、最後が一番下(1段目)。各行は左から6文字 |
| マス | `R` `Y` `G` `B` = 色ぷよ、`#` = おじゃまぷよ、`.` = 空 |
| 色 | 4つの文字は「4色を区別する印」で、画面の色と同じとは限らない(例: 紫が `B` に割り当てられることがある) |
| 組ぷよ `queue` | `["RG","BY",…]`。先頭が今の組ぷよ、次がネクスト、あればネクネク。1文字目が軸ぷよ、2文字目が子ぷよ |
| 座標 `[x, y]` | x は左から0〜5、y は**下から**0〜12 |
| 向き `r` | 軸ぷよから見た子ぷよの位置: `UP` / `RIGHT` / `DOWN` / `LEFT` |

### 要求の種類

| `mode` | いつ来るか | 必須 |
|---|---|---|
| (無し)または `build` | 一人用モード、対戦の最初の手など。相手を考えずに置き場所を聞く | ○ |
| `analyze` | `build` の後に続けて。盤面の連鎖を調べる | ○ |
| `battle` | 対戦モード。相手を見て置き場所を聞く | ○(一人用モードだけで使うなら不要) |

`candidates` など、ほかの `mode` は同梱の YamaNEKO だけに送ります。知らない `mode` には `{"error":"…"}` を返してください。

### build

要求:

```json
{"field":["......","......","......","......","......","......","......","......","......","......","......","......","RG...."],
 "queue":["RG","BY","RR"]}
```

`width`・`depth`(探索の幅・深さの目安)が付くことがあります。無視してかまいません。

答え:

```json
{"x":2,"r":"UP","score":1200,"axis":[2,0],"child":[2,1],"ms":35}
```

| 項目 | 必須 | 内容 |
|---|---|---|
| `x` | ○ | 軸ぷよの列 |
| `r` | ○ | 子ぷよの位置 |
| `score` | ○ | 評価値(整数。大きいほど良い) |
| `axis`, `child` | ○ | 置いた後(落ちた後、連鎖の前)の軸ぷよ・子ぷよのマス |
| `ms` | | 考えた時間(ミリ秒) |
| `field_after` | | 置いて連鎖が終わった後の盤面(13行) |
| `form` | | 狙っている形。`"GTR"` / `"FRON"` / `"SGTR"` / `null` |
| `candidates` | | 候補の一覧 `[{"x":0,"r":"UP","score":1}]` |

### analyze

要求は `{"mode":"analyze","field":…,"queue":…}`(`queue` は2組以上)。答え:

```json
{"immediate":{"count":0,"score":0,"garbage":0,"x":0,"r":"UP","frame":0},
 "max":{"count":2,"score":360,"garbage":5,"x":3,"r":"LEFT","frame":1},
 "harass":{"count":2,"score":360,"garbage":5,"x":3,"r":"LEFT","frame":1},
 "potential":0,"garbage_max":5}
```

| 項目 | 必須 | 内容 |
|---|---|---|
| `immediate` | ○ | 今の組ぷよで撃てる最大の連鎖 |
| `max` | ○ | 見えている組ぷよで撃てる最大の連鎖 |
| `harass` | ○ | 3連鎖以下で撃てる最大の連鎖 |
| `potential` | ○ | 将来の本線の見込みの点(分からなければ 0) |
| `garbage_max` | ○ | `max` をおじゃまの数にしたもの |
| `fire_points` | | 1個置くと連鎖が起きる所 `[{"x":0,"y":3,"color":"R","count":4,"score":2000}]`(点の高い順) |
| `potential_chain` | | 組んでいる連鎖の数 |

連鎖1件の項目はすべて必須です: `count` 連鎖数(無ければ 0)、`score` 点、`garbage` おじゃまの数、`x`・`r` 最初に置く組の置き場所、`frame` 何手目で撃つか(0 = 今の組)。

### battle

要求:

```json
{"mode":"battle","target_point":70,
 "self":{"field":["…13行…"],"queue":["RG","BY"],"attack":0,"attack_frame":0,"dropping":0,
         "all_clear":false,"bonus":0,"chain_bonus":false},
 "enemy":{"field":["…13行…"],"queue":["GG","RY"],"attack":0,"attack_frame":0,"dropping":0,
          "all_clear":false,"bonus":0,"chain_bonus":false}}
```

| 項目 | 内容 |
|---|---|
| `target_point` | おじゃま1個に必要な点(70 から、時間とともに減る) |
| `enemy_unknown` | `true` なら、相手を読めなかったので `enemy` は仮の空の盤面 |
| `field`, `queue` | そのプレイヤーの盤面と組ぷよ |
| `attack` | **そのプレイヤーに降る**予告のおじゃまの数 |
| `attack_frame` | 攻撃している側の連鎖が終わるまでの手数の目安(0 = 攻撃されていない) |
| `dropping` | 落ちてくる途中のおじゃまの数 |
| `all_clear` | 全消しのボーナスを持っている |
| `bonus` | 次の連鎖に足される点 |
| `chain_bonus` | 進行中の連鎖に全消しのボーナスが乗っている |
| `chain_field` | 連鎖中の時だけ付くことがある: 発火する直前の盤面(13行) |
| `attack_frame_est` | 付くことがある: 連鎖が終わるまでに相手が置ける手数の見積もり |
| `carry`, `history`, `placed` | 付くことがある: 攻撃の端数の点・これまでの組ぷよ・置いた数 |

答え:

```json
{"x":2,"r":"UP","eval":1200,"axis":[2,0],"child":[2,1],"label":"build",
 "self":{"immediate":{…},"max":{…},"harass":{…},"potential":0,"garbage_max":0},
 "enemy":{"immediate":{…},"max":{…},"harass":{…},"potential":0,"garbage_max":0},"ms":40}
```

| 項目 | 必須 | 内容 |
|---|---|---|
| `x`, `r`, `axis`, `child` | ○ | build と同じ |
| `eval` | ○ | 評価値(整数) |
| `label` | ○ | 手の意味: `build` 構築 / `main` 本線発火 / `harass` 潰し / `accept` 受け / `all_clear` 全消し / `prepare` 発火の準備 |
| `self`, `enemy` | ○ | それぞれの盤面の analyze の答え |
| `ms`, `form`, `field_after` | | build と同じ |
| `chain_after` | | この手で起きる連鎖 `{"count":5,"score":4840}` |
| `plan_steps` | | 準備の手を含む攻撃なら、撃つまでの手数 |
| `incoming`, `incoming_chain` | | 自分に降ると見積もったおじゃまの数・その連鎖数 |

### エラー

```json
{"error":"no valid placement"}
```

- 置ける所が無い時は、必ず `no valid placement` を返す。本体は提示を消し、次の手番でまた聞く
- それ以外の `error` は、思考エンジンの異常として支援モードを止める
- 盤面は画面から読んだもので、浮いたぷよ・4つつながったぷよが入ることがある。落ちないこと

## 5. うまくいかない時

| 症状 | 原因と対応 |
|---|---|
| 一覧に「(見つかりません)」と出る | exe を移した・消した・隔離された。登録し直す |
| 「5.0秒間応答がありませんでした」(テトリス) | `info` を自分から送っていない、または flush していない |
| 「TBP 互換…の思考エンジンではない可能性」 | 最初の1行が `info` でない。標準出力に JSON 以外を書いている |
| 「ルールを受理しませんでした」 | `rules` に `ready` を返していない |
| 「60.0秒間応答がありませんでした」(ぷよ) | `{"ready":true}` を送っていない、または flush していない |
| 「プロセスが終了しました」 | エンジンが落ちた。DLL が足りない、起動引数が違う、`--config` を知らない など。exe を PowerShell から直接起動すると理由が分かる |
| 登録できるが丸が出ない | 座標が規格と違う(テトリスは中心と下からの y、ぷよは下からの y)。置けない手は表示されない |

動きを手で確かめるには、PowerShell で次のようにします(ぷよのサンプルの例)。

```powershell
'{"field":["......","......","......","......","......","......","......","......","......","......","......","......","......"],"queue":["RG","BY"]}', 'quit' | python -u docs/samples/puyo_engine_sample.py
```
